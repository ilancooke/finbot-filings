# Local CloudFormation validation

These checks do not create AWS resources or require AWS credentials. They cover
the saved bootstrap template and both application templates generated by CDK.
Run commands from the `finbot-filings` repository root after strict synthesis.
No deployment helper script is needed.

## Pinned tools and isolated installation

- cfn-lint **1.57.2**, pinned in `requirements.txt`.
- cfn-guard **3.2.1**, from the official versioned release. The macOS ARM64 archive
  SHA-256 is `4c1eb10c061731159eaaf0e7dbd465db9fa4b767b82186a4ab489671cc00b7d0`.

The following standard commands reproduce the temporary installation used for
the 2026-10-09 review on macOS ARM64. Temporary directories may disappear after
a restart; reinstall if needed. The repository's application and infrastructure
virtual environments are unaffected. Other operating systems need the matching
official Guard release asset and checksum.

```bash
.venv/bin/python -m venv /private/tmp/finbot-cfn-validation-venv
/private/tmp/finbot-cfn-validation-venv/bin/python -m pip install --no-cache-dir \
  -r infra/validation/requirements.txt
curl --fail --silent --show-error --location \
  https://github.com/aws-cloudformation/cloudformation-guard/releases/download/3.2.1/cfn-guard-v3-aarch64-macos-latest.tar.gz \
  --output /private/tmp/finbot-cfn-guard-3.2.1.tar.gz
```

Verify the archive before extracting it. This checksum command must print `OK`:

```bash
echo '4c1eb10c061731159eaaf0e7dbd465db9fa4b767b82186a4ab489671cc00b7d0  /private/tmp/finbot-cfn-guard-3.2.1.tar.gz' | shasum -a 256 -c -
mkdir -p /private/tmp/finbot-cfn-guard-3.2.1
tar -xzf /private/tmp/finbot-cfn-guard-3.2.1.tar.gz \
  -C /private/tmp/finbot-cfn-guard-3.2.1
/private/tmp/finbot-cfn-validation-venv/bin/cfn-lint --version
/private/tmp/finbot-cfn-guard-3.2.1/cfn-guard-v3-aarch64-macos-latest/cfn-guard --version
```

## Run schema and policy checks

First run strict credential-free synthesis as described in
[DEPLOYMENT.md](../../docs/DEPLOYMENT.md). `cdk.out` is generated and ignored by Git.
Then run:

```bash
/private/tmp/finbot-cfn-validation-venv/bin/cfn-lint \
  --format json --regions us-east-1 --non-zero-exit-code error \
  --template infra/bootstrap/bootstrap-template.yaml cdk.out/*.template.json

/private/tmp/finbot-cfn-guard-3.2.1/cfn-guard-v3-aarch64-macos-latest/cfn-guard test \
  --rules-file infra/validation/encryption.guard \
  --test-data infra/validation/encryption_tests.yaml --output-format json

/private/tmp/finbot-cfn-guard-3.2.1/cfn-guard-v3-aarch64-macos-latest/cfn-guard validate \
  --rules infra/validation/encryption.guard \
  --data infra/bootstrap/bootstrap-template.yaml \
  --data cdk.out/finbot-example-state.template.json \
  --data cdk.out/finbot-example-runtime.template.json \
  --output-format json --structured --show-summary none
```

Change the synthesized filenames when using another environment name. The lint
command reports warnings while returning nonzero only for errors; it does not
suppress rules. Review new warnings rather than assuming they match this baseline.

`encryption.guard` is a repository-owned implementation of
[ADR 010](../../docs/adr/010-use-service-managed-encryption-without-kms-integration.md),
not a downloaded industry compliance framework. Its seven rules prohibit KMS
resources and enforce the accepted S3, DynamoDB, SNS, SQS, ECR and Logs encryption
choices. SNS plaintext at rest is intentional. Five Guard fixtures verify accepted
defaults, absent service types, rejected KMS choices and required S3/SQS settings.
The existing CDK pytest suite separately checks IAM grants, HTTPS, private access,
retention and immutable writes. These checks do not certify regulatory compliance
or evaluate IAM permission outcomes in a live account.

## Recorded result (2026-10-09)

All three templates: **0 lint errors, 4 warnings, 0 informational findings**.
No lint rules were suppressed. Reviewed warnings:

| Template and path | Rule / line | Reason retained |
| --- | --- | --- |
| Bootstrap `Parameters/FileAssetsBucketKmsKeyId` | W2001 / 30 | Intentionally unused compatibility input supplied by pinned CDK; cannot select KMS |
| Bootstrap `Parameters/BootstrapVariant` | W2001 / 64 | Upstream CDK variant marker is consumed by the CLI, not a resource |
| Bootstrap `Resources/StagingBucket/Properties/AccessControl` | W3045 / 133 | Upstream private ACL setting preserved; bucket policy, ownership and public-access safeguards remain |
| Runtime `Resources/CustomAWSCDKOpenIdConnectProviderCustomResourceProviderHandlerF2C543E0/DependsOn/0` | W3005 / 881 | Redundant dependency generated by pinned CDK, also enforced by `GetAtt` |

The application state template had no lint findings. Guard validation passed for
all three templates with **0 policy violations**, and all five Guard test fixtures
passed. Rule skips indicate a resource type is absent from that template. Line
numbers refer to this review's source/synthesis and may move on later edits.

CloudFormation account-aware deployment validation has not run. These local checks
do not verify live permissions, account quotas, name availability or deployability.
